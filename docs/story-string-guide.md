# 故事字符串（Story String）是什么、怎么用？

下面用中文解释 UI 里“故事字符串”相关的概念：它是如何被填充、有哪些字段、能放在哪里，以及和“故事字符串前缀/后缀”“故事字符串序列”等控件的对应关系。

## 1. 它是什么

- 故事字符串本质是一个 Handlebars 模板，内容默认存放在 `Context > 故事字符串` 输入框。
- 模板渲染时会把角色卡、世界信息、预设指令等信息塞进模板参数，然后得到一段整体提示词文字。
- 这段文字通常放在“系统提示词”后面，作为模型开局要遵守的背景/规则合集；如果切换到“在聊天上下文插入”，则会变成一条带深度的历史消息注入。

## 2. 模板可以用哪些字段

渲染故事字符串时会组装一批参数，常用字段如下：

- `description`：角色背景/描述。
- `personality`：角色性格。
- `persona`：用户人格描述（仅当位置设为“提示词内”才写入）。
- `scenario`：场景设定。
- `system`：系统提示词文本（仅非 OpenAI 接口时启用）。
- `char` / `user`：角色名 / 用户名，用于宏替换。
- `wiBefore` / `wiAfter`（同名别名 `loreBefore` / `loreAfter`）：命中世界信息插在前后两段的文本。
- `anchorBefore` / `anchorAfter`：扩展模块“故事字符串前缀/后缀”产出的插入片段。
- `mesExamples` / `mesExamplesRaw`：示例对话的拼接文本。

以上字段的组装位置见 `storyStringParams`，也是校验缺失字段时的来源。【F:public/script.js†L4308-L4341】【F:public/scripts/power-user.js†L2219-L2256】

## 3. 渲染与校验流程

1. 读取上下文里的故事字符串模板（可被自定义参数覆盖）。
2. 调用 Handlebars 编译模板，不进行 HTML 转义。
3. 用上面的参数渲染，并补充未写入的 `{{user}}/{{char}}` 宏。
4. 去掉开头多余空行，末尾自动补换行（除非模板被设为“在聊天上下文插入”）。
5. 如果模板缺少 `{{description}}` 等字段但参数中有内容，会弹出一次性黄色警告，方便发现遗漏的占位符。

这些步骤分别在 `renderStoryString()` 和 `validateStoryString()` 中实现。【F:public/scripts/power-user.js†L2219-L2305】

## 4. 插入位置与“故事字符串序列”

渲染出的故事字符串有两种用途：

- **作为提示词正文**：默认放在“故事字符串之后”位置，紧跟系统提示词，直接成为模型的开局背景。此时会按照“故事字符串序列”前缀/后缀包装，适用于指令模式（instruct）。【F:public/scripts/instruct-mode.js†L483-L501】
- **作为历史消息注入**：当上下文设置为“在聊天上下文插入”时，会调用 `setExtensionPrompt` 把结果写入扩展提示，带有自定义深度和角色；为避免重复，正文中的故事字符串会被清空，只保留这条注入消息。【F:public/script.js†L4334-L4344】【F:public/script.js†L8368-L8386】

## 5. 前/后缀、序列、宏的作用

- **故事字符串前缀/后缀**：UI 里的“故事字符串前缀/后缀”会成为 `anchorBefore/anchorAfter`，在模板里用 `{{anchorBefore}}`/`{{anchorAfter}}` 放置。常见用法是给“合并角色卡”后的字段补分隔符。
- **故事字符串序列（Instruct 模式）**：在指令模式下，`story_string_prefix` / `story_string_suffix` 会把故事字符串整体包上一层自定义提示，类似“System:”或“Instruction:”。只有当故事字符串不是“聊天注入”模式时才会应用这层包装。【F:public/scripts/instruct-mode.js†L487-L499】
- **宏替换**：模板和序列都支持 `{{char}}`、`{{user}}`、`{{name}}` 等宏，渲染时会替换为当前对话的角色名、用户名称，方便做个性化提示。

## 6. 在别处复刻的最小步骤

1. 取得角色描述、性格、场景、世界信息、示例对话等文本，按上方字段组成 `params` 对象。
2. 用 Handlebars（或其他模板引擎）渲染故事字符串模板。
3. 需要“上下文注入”时，把结果存成带 `position`/`depth`/`role` 的扩展提示对象；否则直接拼到系统提示后面。
4. 在指令模式下追加前/后缀序列，并留意是否要自动换行。

这样就能在其他项目里复刻 SillyTavern 的故事字符串效果，同时保留 UI 上的那些特殊开关。

## 7. 假设输入与输出示例

为了直观说明，可以假设：

- 故事字符串模板写在 UI 的“Context > 故事字符串”输入框，内容为：

  ```
  {{anchorBefore}}
  角色设定：{{description}}
  性格：{{personality}}
  场景：{{scenario}}
  世界信息（前）：{{wiBefore}}
  世界信息（后）：{{wiAfter}}
  示例对话：
  {{mesExamples}}
  {{anchorAfter}}
  ```

- 世界信息命中了两条，合并成：

  - `wiBefore = "[村庄传闻] 玩家正在调查失踪事件。"`
  - `wiAfter = "[线索] 夜晚会听到奇怪的铃声。"`

- “故事字符串前缀/后缀”分别填了：

  - `anchorBefore = "--- 故事开始 ---"`
  - `anchorAfter = "--- 故事结束 ---"`

- 示例对话（Message Examples）里有一条：

  ```
  User: 你是谁？
  Assistant: 我是村里的向导，可以帮你打听消息。
  ```

- 角色卡字段（或角色合并后的字段）提供了：

  - `description = "热心的村庄向导，熟悉当地风土。"`
  - `personality = "友好、健谈、乐于助人。"`
  - `scenario = "傍晚在村口的篝火旁与玩家交谈。"`

### 7.1 作为提示词正文的渲染结果

当“故事字符串位置”保持默认（提示词内）时，渲染得到的正文示例：

```
--- 故事开始 ---
角色设定：热心的村庄向导，熟悉当地风土。
性格：友好、健谈、乐于助人。
场景：傍晚在村口的篝火旁与玩家交谈。
世界信息（前）：[村庄传闻] 玩家正在调查失踪事件。
世界信息（后）：[线索] 夜晚会听到奇怪的铃声。
示例对话：
User: 你是谁？
Assistant: 我是村里的向导，可以帮你打听消息。
--- 故事结束 ---
```

如果开启指令模式且填了 `story_string_prefix/suffix`，上面的整块文本会再被对应前缀/后缀包装一次，作为模型需要遵守的系统级提示发送给 OpenAI。

### 7.2 作为聊天上下文注入的渲染结果

当选择“在聊天上下文插入”时，渲染得到的同样文本会被封装成一条历史消息（可指定角色与深度），并写入扩展提示，类似：

```
role: system
depth: 3
text:
--- 故事开始 ---
角色设定：热心的村庄向导，熟悉当地风土。
性格：友好、健谈、乐于助人。
场景：傍晚在村口的篝火旁与玩家交谈。
世界信息（前）：[村庄传闻] 玩家正在调查失踪事件。
世界信息（后）：[线索] 夜晚会听到奇怪的铃声。
示例对话：
User: 你是谁？
Assistant: 我是村里的向导，可以帮你打听消息。
--- 故事结束 ---
```

此时正文里的故事字符串会被清空，避免重复；模型在截取上下文时会按照深度把这条注入消息排在靠前的位置，让背景信息优先进入预算。【F:public/script.js†L4334-L4344】【F:public/script.js†L8368-L8386】
